What it does

A forge for knowledge, not a black box.

Every concept okfsmith emits carries provenance (sources[]), a trust tier, and lifecycle metadata — and every bundle passes a built-in §11 validator. Here is what ships today.

Incremental sync

okfsmith sync processes only new, changed, renamed, or deleted sources — with --watch, --dry-run, and text or JSON output. Re-ingest without the wait.

Trust tiers & provenance

Every concept carries sources[] citations and a generated / verified trust tier. Answers trace back to the exact document they came from.

Temporal model

Validity and supersession are first-class: concepts expire and get replaced, and --as-of lets you query the bundle as it looked on any date.

One-command MCP server

okfsmith mcp serves any bundle over stdio, SSE, or streamable HTTP — with index, search, get, and neighbors tools, plus traverse and diff.

Eval & CI gating

okfsmith eval runs golden-set Q&A with RAG Triad scores and a retrieval-vs-generation diagnosis — and a --fail-under gate for CI pipelines.

Governed write-back

MCP write tools are trust-tier gated: agents can update the bundle through preview/write/audit flows that respect the same tiers reading does.

Similarity deduplication

The extraction pipeline merges near-duplicate entities with stemmed-token Jaccard similarity — dependency-free, offline, and deterministic.

Web dashboard

okfsmith dashboard opens a local, token-secured UI: drag-and-drop ingest with live progress, an interactive knowledge graph, grounded chat, validation, and eval.

Grounded chat

okfsmith chat is a REPL over your bundle that answers with [concept-id] citations. No relevant concepts, no invented answer.

How it works

Sixty seconds to a bundle.

Install, scaffold a bundle, ingest offline, validate, and visualize — then point any MCP-capable agent at it.

terminal 
$ pip install okfsmith

$ okfsmith init ./kb
$ okfsmith ingest ./kb notes/ report.pdf --no-llm   # offline first pass
$ okfsmith validate ./kb
$ okfsmith graph ./kb --format html   # writes ./kb/viz.html

# Point any MCP-capable agent at the bundle:
$ pip install "okfsmith[mcp]"
$ okfsmith mcp ./kb
01

Init

Scaffold a bundle with index.md and log.md. One command, no config files.

02

Ingest

Parse PDFs, Markdown, Office docs, or whole folders. --no-llm gives a fast, offline, deterministic first pass.

03

Validate

Check OKF §11 conformance — hard rules E001–E004 plus advisory lints for dead links, orphans, and stubs.

04

Serve

One MCP command exposes the bundle to any capable agent, every answer traced to sources[].

Anatomy of a concept

Not just markdown. Markdown with a memory.

A folder of markdown can't tell you where a claim came from, whether a human checked it, or when it expires. An OKF bundle can — in plain YAML any tool can read.

courses/cs101.md — real example bundle 
---
type: Course
title: "CS 101: Introduction to Programming"
description: A first programming course…
tags: [programming, python, introductory]
sources:
  - id: python-tutorial
    resource: https://docs.python.org/3/tutorial/
  - id: sicp
    resource: https://web.mit.edu/…/sicp.pdf
generated:
  by: okfsmith/manual
verified:
  - by: human:bilal
status: stable
stale_after: 2027-09-26
---

Provenance, trust, and time — in every file.

Only type is required by the OKF spec. okfsmith adds the metadata that makes a bundle safe to act on:

  • Provenance. sources[] records exactly which documents each concept came from — deduped by SHA-256.
  • Trust tiers. generated vs verified metadata separates machine drafts from human-checked knowledge.
  • Lifecycle. status, supersession, and stale_after let knowledge expire on purpose, not by accident.
  • §11 validator. Hard conformance rules E001–E004, plus advisory lints. Broken links are warnings, never errors.

Grounded chat that refuses to guess.

A Claude Code / Gemini CLI style REPL over your bundle. With a local Ollama or any API key, answers are synthesized and grounded; without one, extractive mode shows the keyword-matched concepts themselves.

  • Citations on every answer. Each reply names its [concept-id] and lists its sources.
  • Honest by construction. No relevant concepts, no invented answer — it shows you what it found instead.
  • Full slash-command set. /ingest, /search, /validate, /graph, /doctor and more, without leaving the REPL.

For your agents

One command. Any MCP-capable agent.

The bundle is the product; the MCP server is how agents read it. Every answer traces back to sources[] in the bundle.

terminal 
$ pip install "okfsmith[mcp]"
$ okfsmith mcp ./kb

# transports: stdio · SSE · streamable HTTP
# tools: index · list · search · get ·
#        neighbors · traverse · diff

Read freely. Write carefully.

Point Claude, Codex, or any MCP client at a bundle and it can search, read, and walk the concept graph. When agents write back, the same trust tiers that govern reading govern writing.

  • Five core tools. index, list, search, get, neighbors — plus graph traverse and bundle diff.
  • Governed write-back. Preview / write / audit flows, gated by trust tier.
  • Skill pack included. skills/okfsmith-build/SKILL.md teaches agents the init → ingest → validate → serve loop.
Bring your own model — or none

Offline by default. Any provider when you want one.

--no-llm ingests fully offline, no key, no network. Add a model only for richer extraction — Ollama locally, or one key for any hosted provider. Keys are never logged, never shown, never written to disk.
