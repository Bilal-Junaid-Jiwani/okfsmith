From raw ore to a finished bundle, in seven heats.

Clean markdown already has good tooling. The messy middle is where knowledge actually lives: 200-page PDFs with broken reading order, sprawling Notion exports, wiki dumps. That is what okfsmith ingests first.

A forge for knowledge, not a black box.

Every concept okfsmith emits carries its sources, a trust tier, and lifecycle metadata, and every bundle passes the built-in validator. Here is what ships today.

FOR YOUR AGENTS

One-command MCP server
okfsmith mcp serves any bundle over stdio, SSE, or streamable HTTP, with index, search, get, and neighbors tools, plus traverse and diff.
Grounded chat
okfsmith chat is a REPL over your bundle that answers with concept citations. No relevant concepts, no invented answer. It shows you what it found instead.
Web dashboard
okfsmith dashboard opens a local, token-secured UI: drag-and-drop ingest with live progress, an interactive knowledge graph, grounded chat, validation, and eval.

TRUST, CHECKED IN

Provenance and trust tiers
Every concept carries sources[] citations and a generated or verified tier. Answers trace back to the exact document they came from.
Section 11 validator
The spec's hard conformance rules, E001 to E004, run on every bundle, with advisory lints for dead links, orphans, and stubs. Broken links are warnings, never errors.
Temporal model
Validity and supersession are first-class: concepts expire and get replaced, and --as-of lets you query the bundle as it looked on any date.

KEPT CURRENT

Incremental sync
okfsmith sync processes only new, changed, renamed, or deleted sources, with --watch, --dry-run, and text or JSON output. Re-ingest without the wait.
Similarity deduplication
The extraction pipeline merges near-duplicate entities with stemmed-token Jaccard similarity. Dependency-free, offline, and deterministic.
Eval and CI gating
okfsmith eval runs golden-set question answering with RAG Triad scores and a retrieval-versus-generation diagnosis, and a --fail-under gate for CI pipelines.
Governed write-back
MCP write tools are trust-tier gated: agents can update the bundle through preview, write, and audit flows that respect the same tiers reading does.

Sixty seconds to a bundle.

Install, scaffold a bundle, ingest offline, validate, and draw the graph. Then point any MCP-capable agent at it.

TERMINAL
$ pip install okfsmith

$ okfsmith init ./kb

$ okfsmith ingest ./kb notes/ report.pdf --no-llm
  # offline first pass

$ okfsmith validate ./kb

$ okfsmith graph ./kb --format html
  # writes ./kb/viz.html, open it in a browser
  1. Init

    Scaffold a bundle with index.md and log.md. One command, no config files.

  2. Ingest

    Parse PDFs, Markdown, Office docs, or whole folders. --no-llm gives a fast, offline, deterministic first pass.

  3. Validate

    Check section 11 conformance: hard rules E001 to E004 plus advisory lints for dead links, orphans, and stubs.

  4. Serve

    One MCP command exposes the bundle to any capable agent, every answer traced to sources[].

Not just markdown. Markdown with a memory.

A folder of markdown cannot tell you where a claim came from, whether a human checked it, or when it expires. An OKF bundle can, in plain YAML that any tool can read. Only type is required by the OKF spec. okfsmith adds the metadata that makes a bundle safe to act on:

sources[] Provenance. Records exactly which documents each concept came from, deduped by SHA-256.
generated / verified Trust tiers. Separates machine drafts from human-checked knowledge, so agents know what to lean on.
status / stale_after Lifecycle. Concepts carry a status and an expiry, and superseded concepts point at what replaced them. Knowledge expires on purpose, not by accident.
the validator Hard conformance rules E001 to E004, plus advisory lints for dead links, orphans, and stubs. Broken links are warnings, never errors, per spec section 6.

Bring your own model, or none

--no-llm ingests fully offline, no key, no network. Add a model only for richer extraction: Ollama locally, or one key for any hosted provider. Keys are never logged, never shown, never written to disk.

openrouter, anthropic, openai, gemini, groq, mistral, deepseek, together, fireworks, deepinfra, anyscale, perplexity, xai, agentrouter, lmstudio, ollama, plus any OpenAI-compatible endpoint via --api-base.

Install it your way.

The base install is offline-first. Extras add Office parsing, the MCP server, or OCR, only if you want them.

$ pip install okfsmith
$ pip install "okfsmith[office]" # DOCX, PPTX, XLSX
$ pip install "okfsmith[mcp]" # MCP server
$ pip install "okfsmith[ocr]" # Docling OCR sidecar
$ pipx install "okfsmith[office,mcp]"
$ okfsmith doctor # verify your setup

The Open Knowledge Format (v0.2), Google's spec for portable knowledge bundles: markdown files with YAML frontmatter plus reserved index.md and log.md files. Canonical reference: GoogleCloudPlatform/open-knowledge-format on GitHub.

It enforces the OKF section 11 conformance rules (validate), tracks provenance and trust tiers, dedups sources by SHA-256, links concepts into a graph, and serves the bundle to agents over MCP, while keeping everything as plain markdown you can read without the tool.
