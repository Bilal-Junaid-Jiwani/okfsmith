Baseline materials: `README.md`, `docs/OVERVIEW.md`, `pyproject.toml`, `examples/bundles/`, `/tmp/wt-cli/src/okfsmith/cli/commands.py` (415 lines), `app.py`, plus `.contract/fixtures/` and `.contract/spec_decisions.md`. ## Rubric scores (0–10)

1. **CLI UX — 5.5 (provisional).** Typer gives free `--help` and Rich tables give the `ingest`/`validate`/`list` output a polished terminal feel; error messages are consistent (`error:` prefix, exit 1, no raw tracebacks). But the CLI is half-plumbed: `validate`, `mcp`, and `graph --format html` die with "not available on this branch yet" until sibling slices land; `add_completion=False` is set with zero shell completions shipped; there is no `-h` short-help vs `--help` full-help split; and `okfsmith ingest ./kb <source>` in the README **does not match** the real signature (`ingest SOURCE --bundle ./kb`) — a doc/CLI drift that will confuse every first-time user.
2. **README quality — 7.5.** Strong elevator pitch ("Forge messy documents into OKF v0.2 bundles"), a genuine 60-second quickstart, an honest comparison table with explicit anti-framing, a trust-tier table, an env-var config table, and a roadmap that names what v1 will *not* do. Weak spots: the PyPI/version/license badges link to `pypi.org/project/okfsmith/` and GitHub paths that do not exist yet (404 badges on the landing page); no terminal screenshot or demo GIF of actual output; the CLI reference table contradicts the real Typer signatures; no install matrix beyond `pip install okfsmith` (no uvx/uv-only path documented, no platform notes).
3. **Docs — 6.0.** `docs/OVERVIEW.md` is a genuinely good architecture doc (ASCII pipeline diagram, per-stage details, cross-cutting constraints), and `.contract/spec_decisions.md` is an excellent implementer cheat-sheet. But `docs/` holds exactly one file; the README advertises a "SKILL.md pack" that does not exist in the repo; there is no FAQ/troubleshooting, no user guide (ripgrep-style `GUIDE.md`), no man page, and no configuration-reference doc.
4. **Packaging/distribution — 3.5.** `pyproject.toml` is correct and modern (`[project.scripts]` entry point `okfsmith`, optional `mcp`/`ocr`/`test` extras, Apache-2.0 classifier, `requires-python >=3.10`). Everything else is missing: no PyPI release (name verified free, repo not yet created), no `CHANGELOG.md`, no shell completions, no man page, no install script or single-binary equivalent, no CI/release workflow in the repo, no trusted-publisher/OIDC plan for PyPI.
5. **Code quality — 6.5 (provisional).** The thin-CLI/fat-core split the README promises is actually real: commands wire input to `okfsmith.core` and lazy-import sibling slices with clean, user-friendly failures instead of `ImportError` tracebacks; per-file failure tolerance in `ingest` is good CLI citizenship; there are typed signatures, docstrings, and core smoke tests. Gaps: all 7 commands live in one 415-line `commands.py` monolith; zero CLI tests (only `tests/test_core_smoke.py`); `--format` is a free string validated by hand instead of a constrained choice; one broad `except Exception` swallows error classes that could drive better messages.
6. **Demo/onboarding — 4.5.** The README quickstart is four commands to a validated bundle, and `examples/bundles/` ships two real, spec-validated demo bundles (cs-curriculum, okf-primer — 13 concepts, trust tiers in action, honest "fictional curriculum" framing). Missing: no demo GIF/asciinema/screencast of real terminal output (every benchmark tool leads with one), no screenshots of `validate`/`list` output, no `okfsmith demo`/sample-data command, and the `uvx okfsmith mcp` quickstart step cannot work until the first PyPI release.

## Per-tool pattern notes — what to steal

- **sharkdp/bat.** *Steal:* screenshots of rendered output as the first thing on the README (value visible in one screenful); platform-by-platform install matrix; per-shell "integration with other tools" section; config-file support (`~/.config/bat/config`) so repeat flags don't need retyping; smart TTY behavior (plain output when piped); a `doc/release-checklist.md` pattern for release hygiene. *Weakness to avoid:* sprawling README that duplicated everything the man page already says — later versions thinned it. okfsmith should keep flags in `--help` and put narrative in docs.
- **sharkdp/fd.** *Steal:* demo-first README (screencast, then bite-size command→output subsections); `fd -h` concise vs `fd --help` detailed help split; a Troubleshooting section that answers "fd does not find my file!" verbatim; sensible opinionated defaults stated up front (smart case, respects .gitignore). *Weakness to avoid:* no config-file story at all. For okfsmith: adopt the `-h`/`--help` split and add a Troubleshooting section answering "validate says X, what do I do?"
- **BurntSushi/ripgrep.** *Steal:* one-sentence README definition; paired "Why should I use / Why shouldn't I use" sections (honest trust); benchmark tables with real numbers; thin README that defers flags to `--help`, the man page, and an in-repo `GUIDE.md`; `RIPGREP_CONFIG_PATH` config-file convention; `RELEASE-CHECKLIST.md` with signed tags and checksums. *Weakness to avoid:* ripgrep's flag list grew to 100+ and `--help` became a wall — okfsmith should keep commands few and group options with help-panel headings. Also steal the "playground" idea: a way to try before installing (`uvx` fills this role once released).
- **eza-community/eza.** *Steal:* demo GIF + screenshots early; man page shipped in-repo (`man/` directory) and referenced from the README; completions shipped in-repo (`completions/`); install matrix delegated to a separate `INSTALL.md`; `EZA_CONFIG_DIR`/`$XDG_CONFIG_HOME` config-file convention. *Weakness to avoid:* cluttered sponsorship banners at the very top of the README — keep okfsmith's hero clean.
- **junegunn/fzf.** *Steal:* batteries-included shell integration generated by the binary itself (`fzf --bash`, `fzf --zsh`, `fzf --fish`, `fzf --nushell`); first-class install matrix per platform; environment-variable customization table (`FZF_DEFAULT_OPTS`-style); man page in `man/man1`; examples section that doubles as a cookbook. *Direct steal:* `okfsmith completions <shell>` or `okfsmith --init bash`-style output would beat shipping static completion files.
- **starship/starship.** *Steal:* README as minimal landing page with docs on a real site (starship.rs) — full config reference lives outside the README so it can't drift; per-OS install table with copy-paste commands; "Step 1 / Step 2 / Step 3" onboarding structure; presets gallery for instant gratification; `starship init <shell>` pattern (same lesson as fzf). *Weakness to avoid:* an install script (`curl | sh`) is the primary path — fine for starship, but okfsmith's primary path should stay `pip`/`uvx` with a static install as backup.
- **ajeetdsouza/zoxide.** *Steal:* "Getting started" with copy-paste command→comment lines before any install detail; interactive `zi` mode using fzf (compose with ecosystem tools instead of rebuilding); 4-step install numbered list; honest per-distro caveats (struck-through packages that don't exist). *Weakness to avoid:* nothing major; zoxide is the best README-as-landing-page in this set — okfsmith's quickstart should look like it.
- **dandavison/delta.** *Steal:* `delta -h` (short help) vs `delta --help` (full manual) — the cleanest help-tiering in the set; online user manual linked from every README section; screenshot-per-feature layout so each feature is visually legible; "Get Started" as three copy-paste commands. *Weakness to avoid:* config is gitconfig-only and discoverability suffers — okfsmith should document config resolution order explicitly.

## TOP 10 ACTIONABLE GAPS for the builder (ranked by impact)

1. **README CLI reference contradicts the real CLI signatures.** Evidence: README shows `okfsmith ingest ./kb <source>…`, `okfsmith validate ./kb`, `okfsmith read ./kb <concept>`; the Typer app implements `ingest SOURCE --bundle ./kb`, `validate DIRECTORY`, `read DIRECTORY CONCEPT_ID`. Fix: regenerate the reference table from actual `--help` output (and gate it in CI). Effort: **S**.
2. **No shell completions; `add_completion=False` is a dead end.** Evidence: `app.py` sets `add_completion=False` with no replacement. Fix: add `okfsmith completions <bash|zsh|fish|powershell>` emitting scripts (fzf/zoxide pattern — self-generating beats static files), and document install in README. Effort: **M**.
3. **No man page.** Evidence: none in repo; every benchmark tool ships one (fd `doc/`, eza `man/`, fzf `man/man1`, bat CI-generated). Fix: write `man/man1/okfsmith.1`, reference from README, package it in the sdist. Effort: **M**.
4. **Demo/onboarding is text-only — no GIF, screencast, or output screenshots.** Evidence: README has zero images; fd/bat/eza/zoxide/delta all lead with visual proof. Fix: record an asciinema/screencast SVG of the 60-second quickstart (`init → ingest --no-llm → validate → list`) plus one screenshot of `validate` output; embed in README and `docs/`. Effort: **M**.
5. **No CHANGELOG.md, no release process, no PyPI release.** Evidence: single scaffold commit, no CHANGELOG, no CI, badges point at 404s. Fix: start Keep-a-Changelog `CHANGELOG.md`, add a ripgrep-style `RELEASE-CHECKLIST.md` (version bump, signed tag, sdist+wheel, checksums), then do the first `0.1.0` release to PyPI. Effort: **L**.
6. **No `-h` short help vs `--help` full help; long help texts are missing.** Evidence: all commands have one-sentence docstrings; `--format` help is a free string. Fix: adopt fd/delta tiering — concise `-h`, detailed `--help` with examples in the epilog; make `--format` a constrained choice with a real default. Effort: **S**.
7. **Config story is env-vars-only and incomplete.** Evidence: README documents three env vars; bat/ripgrep/eza all add a config file (`$XDG_CONFIG_HOME/okfsmith/config`) and document resolution order (flags > env > config > defaults). Fix: add a small TOML config loader for model tier, strict mode, output format; document precedence in README + a `docs/CONFIGURATION.md`. Effort: **M**.
8. **README advertises a "SKILL.md pack" that does not exist.** Evidence: Features list claims it; `find . -name "SKILL*"` returns nothing. Fix: either ship `examples/skills/okfsmith/SKILL.md` or remove the claim before the first release. Effort: **S**.
9. **One 415-line `commands.py` monolith; zero CLI tests.** Evidence: all 7 commands in one module; `tests/` has only core smoke tests. Fix: split into `cli/commands_{init,ingest,validate,query,serve}.py` (thin CLI/fat core already justifies it) and add Typer `CliRunner` tests per command, including the `_lazy_attr` missing-slice path and exit codes. Effort: **M**.
10. **No troubleshooting/FAQ and no user guide beyond OVERVIEW.md.** Evidence: `docs/` holds one file; fd's "fd does not find my file!" section and ripgrep's FAQ/GUIDE.md answer the questions users actually ask. Fix: add `docs/GUIDE.md` (conceptual walkthrough) and a Troubleshooting section covering "validate says INVALID", "ingest found 0 files", "slice not available" errors, and model/Ollama setup. Effort: **M**.

Honorable mention (not top-10, borderline): `examples/bundles/cs-curriculum/instructors/grace-hopper.md` uses a real person's name in fictional demo content — fine under the "honest framing" rule, but rename to a clearly fictional instructor if any reviewer flags it.
